# Weekly Market Prep Report

Бот в Telegram, который присылает два независимых автоматических отчёта.
Ничего не требует от компьютера — всё работает через GitHub Actions по расписанию.

## Секреты репозитория (уже должны быть добавлены)
Settings → Secrets and variables → Actions:
- `TELEGRAM_BOT_TOKEN` — токен бота из @BotFather
- `TELEGRAM_CHAT_ID` — ваш chat_id в Telegram
- `TWELVE_DATA_API_KEY` — бесплатный ключ с twelvedata.com

# Отчёт 1: подготовка к неделе (календарь + диапазоны + уровни)

Файлы: `weekly_market_prep.py`, `.github/workflows/weekly_market_prep.yml`,
`docs/economic_calendar.ics`

## Что внутри
- Экономический календарь по USD на неделю (High/Medium impact события,
  время конвертируется в московское) — источник: бесплатный публичный
  фид Forex Factory
- Средний недельный диапазон (за последние 8 недель) по EURUSD и XAUUSD
- Ключевые уровни на неделю: high/low прошлой недели + классические
  пивоты (P, R1, R2, S1, S2) по EURUSD и XAUUSD
- Календарь также публикуется как файл `docs/economic_calendar.ics` —
  на него можно подписаться с телефона (Apple Calendar / Google Calendar),
  события появятся прямо в обычном календаре

Расписание: каждое воскресенье в 15:00 UTC.

## Данные о ценах: Twelve Data
Используется вместо Alpha Vantage, поскольку тот не поддерживает XAU/USD
(золото) в бесплатном тарифе. Twelve Data — 800 запросов/день бесплатно,
поддерживает и валютные пары, и золото.

## Подписка на календарь с телефона
GitHub Pages публикует ICS-файл по адресу вида:
```
https://<ваш-username>.github.io/Weekly-Market-Prep-Report/economic_calendar.ics
```
(включается в Settings → Pages → Source: Deploy from a branch → main → /docs)

- iPhone: Настройки → Календарь → Учётные записи → Добавить → Другое →
  Подписной календарь → вставить ссылку
- Android/Google Calendar: calendar.google.com → Другие календари → "+" →
  Подписаться по URL → вставить ссылку

Обновление подписки на стороне Apple/Google происходит не мгновенно
(обычно от нескольких часов до суток) — это ограничение их приложений.

# Отчёт 2: топ-10 акций S&P 500 по росту за последние 3 месяца

Файлы: `monthly_top_gainers.py`, `.github/workflows/monthly_top_gainers.yml`

Секретов не требует — использует те же, что уже в репозитории.

## Что делает
1. Берёт список S&P 500 из бесплатного открытого датасета на GitHub
2. Считает **скользящее окно** — ровно 3 месяца назад от вчерашнего дня
   (не календарный квартал; окно каждый месяц сдвигается на месяц вперёд)
3. Через Twelve Data батч-запросом получает цены закрытия на начало и
   конец этого окна по всем акциям
4. Считает % роста цены за период, берёт топ-10, шлёт в Telegram

Расписание: 2-го числа каждого месяца в 12:00 UTC.

## Важно понимать
- Это НЕ календарный квартал (Q1/Q2/...), а именно "последние 3 месяца
  на сегодня" — отчёт обновляется каждый месяц, окно каждый раз сдвигается
- Акции с неполными данными за период (например, недавние IPO) автоматически
  пропускаются — в сообщении указывается, сколько акций реально учтено
- Список S&P 500 подтягивается заново при каждом запуске, так что изменения
  состава индекса учитываются автоматически
- **Запуск занимает 1.5-2 часа.** Бесплатный тариф Twelve Data разрешает
  только 8 кредитов в минуту (не 8 запросов, как можно подумать из
  описания) — а на ~500 акций нужно ~500 "кредитов". На практике лимит
  срабатывает даже при аккуратном расчёте впритык к 8/минуту, поэтому
  скрипт запрашивает по 6 тикеров за раз (с запасом) с паузой ~75 секунд,
  плюс автоматически повторяет попытку с увеличивающейся паузой при сбоях.
  Это ожидаемое поведение, не зависание — в логе будут строки вида
  "Rate limited" / "Waiting Ns and retrying" по ходу выполнения, это
  нормально. Наберитесь терпения при первом ручном запуске для проверки

# Общие технические примечания

- Оба отчёта независимы друг от друга и от отдельного репозитория с CFTC-отчётом
  (`forex-sentiment-bot`, если он у вас есть) — ничего не пересекается
- Все скрипты используют только бесплатные источники данных (без скрытых
  платных подписок)
- Если что-то не приходит — сначала смотрите лог соответствующего workflow
  в разделе Actions: шаг с названием скрипта покажет точную причину ошибки

# Отчёт 3: новые эпизоды подкаста Morgan Stanley "Thoughts on the Market"

Файлы: `ms_insights_digest.py`, `.github/workflows/ms_insights_digest.yml`

Секретов не требует сверх того, что уже в репозитории (Telegram + опционально
`ANTHROPIC_API_KEY` для ИИ-саммари).

## Что делает
1. Проверяет страницу подкаста:
   https://www.morganstanley.com/insights/podcasts/thoughts-on-the-market
   (там сразу список последних выпусков, не только один)
2. Сравнивает найденные эпизоды со списком уже виденных (файл
   `seen_podcasts.json`, обновляется автоматически после каждого запуска)
3. Для каждого нового эпизода: полная расшифровка отправляется в Claude API
   с запросом на структурированное краткое содержание сразу на русском
   (имя/должность спикера, 2-4 ключевые темы с цифрами и фактами, вывод
   для инвестора). Если ключ не задан или запрос не удался — автоматический
   откат на бесплатный локальный алгоритм (см. ниже).

Расписание: каждый день в 08:00 UTC. Статьи убраны из этого отчёта — только
подкаст.

## ⚠️ Если у вас уже стоит предыдущая версия — сбросьте файл состояния
Если вы уже разворачивали более раннюю версию этого отчёта (со статьями и
файлом `seen_insights.json`), обязательно сделайте следующее ПЕРЕД тем как
заливать новую версию:

1. Удалите старый файл `seen_insights.json` из репозитория (или очистите
   его содержимое) — он относится к другому источнику и вызовет путаницу.
2. Не создавайте `seen_podcasts.json` вручную — скрипт создаст его сам при
   первом запуске.

Это важно, потому что новая страница показывает сразу ~15-20 последних
эпизодов подкаста (за несколько недель), а не 1-2, как раньше. Без сброса
состояния скрипт на первом же запуске попытается разом прислать саммари по
всем этим "новым для него" эпизодам — сразу пачку сообщений и ненужный
расход API. С чистым состоянием первый запуск, как и раньше, тихо запомнит
текущий список как точку отсчёта, ничего не отправляя, а уведомления
начнутся с следующего запуска.

## Первый запуск — без сообщений, это нормально
При самом первом запуске (или после сброса состояния) `seen_podcasts.json`
ещё не существует — скрипт запоминает все эпизоды, которые видит сейчас,
как отправную точку, и НЕ шлёт ничего в Telegram. Уведомления начнут
приходить со следующего запуска, когда выйдет новый эпизод.

## Краткое содержание: Claude API (платно, по токенам)
**Получить ключ:**
1. Зарегистрируйтесь на [console.anthropic.com](https://console.anthropic.com)
2. Пополните баланс (минимальное пополнение обычно $5)
3. Создайте API-ключ в разделе API Keys

**Добавить секрет в репозиторий:**
- Name: `ANTHROPIC_API_KEY`
- Secret: ваш ключ

**Стоимость:** используется модель Claude Sonnet 5. Один эпизод подкаста
(транскрипт ~700-1500 слов + саммари на русском) стоит **меньше 1-2 центов**.
При ежедневных новых эпизодах (будни) — это около $0.20-0.40 в месяц.
Актуальные цены всегда можно проверить на
[anthropic.com](https://www.anthropic.com/pricing).

**Без ключа** — скрипт не сломается: используется бесплатный локальный
алгоритм суммаризации + перевод через MyMemory (качество ниже, но
бесплатно).

## Важно понимать — это экспериментальная часть
Логика разбора HTML была написана и проверена на структуре соседней
страницы Morgan Stanley (`/insights`), где парсинг эпизодов и транскриптов
уже подтверждённо работает на реальных данных. Страница самого подкаста
использует, по всей видимости, тот же шаблон карточки эпизода, поэтому
парсинг должен сработать и здесь — но именно на этой конкретной странице
логика отдельно не проверялась. Если в логе "found 0 podcast episodes" —
принесите лог сюда, поправим. Также у крупных корпоративных сайтов иногда
стоит защита от ботов, блокирующая облачные IP (как было с Myfxbook) — если
увидите ошибку 403, это тот самый случай.
