# Автоматическая подготовка к торговле в Telegram

Набор независимых отчётов, которые GitHub Actions по расписанию собирает и
присылает в один Telegram-бот. Каждый отчёт живёт в своём скрипте и своём
workflow, поэтому поломка одного не влияет на остальные.

Репозиторий публичный: для публичных репозиториев минуты GitHub Actions
бесплатны и не ограничены. Из-за этого сюда нельзя класть ничего личного:
ключи и токены хранятся только в Secrets, а сделки лежат в Google-таблице,
ссылка на которую тоже хранится в Secrets.

CFTC-отчёт по позиционированию (пятница) вынесен в отдельный репозиторий
`forex-sentiment-bot` и в этом README не описан.

## Все отчёты

| # | Отчёт | Файл | Когда приходит (UTC / МСК) | Секреты помимо Telegram | Файл состояния |
|---|---|---|---|---|---|
| 1 | Подготовка к неделе + календарь для телефона | `weekly_market_prep.py` | воскресенье 15:07 / 18:07 | `TWELVE_DATA_API_KEY` | `docs/economic_calendar.ics` |
| 2 | Топ-10 по росту за 3 месяца | `monthly_top_gainers.py` | 2-го числа, 12:00 / 15:00 | `TWELVE_DATA_API_KEY` | `top10_companies.json` |
| 3 | Разбор компаний из топ-10, по одной в день | `company_deepdive.py` | ежедневно 09:00 / 12:00, но шлёт только в 10 дней после отчёта 2 | `ANTHROPIC_API_KEY` | `deepdive_sent_state.json` |
| 4 | Дайджест подкаста Morgan Stanley | `ms_insights_digest.py` | ежедневно 18:00 / 21:00 | `ANTHROPIC_API_KEY` (необязательно) | `seen_podcasts.json` |
| 5 | Статистика торгового журнала | `trading_journal_digest.py` | 2-го числа, 09:00 / 12:00 | `JOURNAL_SHEET_CSV_URL` | нет |
| 6 | Напоминания о событиях календаря | `calendar_reminders.py` | каждые 10 минут (:04, :14, :24 ...) | нет | `reminded_events.json` |

МСК = UTC+3, без перехода на летнее время.

## Общая настройка (один раз)

1. **Telegram-бот.** Создайте бота у `@BotFather`, сохраните токен. Напишите
   боту любое сообщение и откройте
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`: в ответе
   `"chat":{"id":...}` и есть ваш `chat_id`.
2. **Secrets.** Settings → Secrets and variables → Actions → New repository
   secret. Всегда нужны `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Остальные
   добавляются по таблице выше.
3. **Права на запись.** Settings → Actions → General → Workflow permissions →
   Read and write permissions → Save. Без этого отчёты, которым нужно
   сохранять файл состояния, падают на шаге коммита.
4. **Файлы.** Каждый отчёт состоит из скрипта в корне репозитория и файла
   `.github/workflows/<имя>.yml`. Создавайте их через Add file → Create new
   file, указывая полный путь.
5. **Проверка.** Actions → нужный workflow → Run workflow. Через минуту
   проверьте Telegram.

Если отчёт не пришёл в срок, первым делом запустите его вручную. Расписание
GitHub не гарантирует запуск (см. раздел про надёжность ниже).

## 1. Подготовка к неделе

`weekly_market_prep.py`, workflow `weekly_market_prep.yml`.
Расписание: воскресенье 15:07 UTC (18:07 МСК).

Что приходит:
- экономический календарь по USD на неделю (события High и Medium, время в МСК),
  источник: бесплатный фид Forex Factory;
- средний недельный диапазон за последние 8 недель по EURUSD и XAUUSD;
- максимум и минимум прошлой недели и классические пивоты (P, R1, R2, S1, S2).

Цены берутся из Twelve Data (бесплатный тариф: 800 кредитов в день, 8 в
минуту; скрипт делает 2 запроса). Alpha Vantage не подходит: его недельный
endpoint для валют не поддерживает золото. Если запуск вручную приходится
на середину недели, текущая незакрытая неделя в статистику не входит.

### Календарь на телефоне (ICS)

Каждый запуск обновляет `docs/economic_calendar.ics`. Файл раздаётся через
GitHub Pages: Settings → Pages → Deploy from a branch → ветка `main`, папка
`/docs`. Ссылка:

```
https://vdorogov89.github.io/Weekly-Market-Prep-Report/economic_calendar.ics
```

Подписка: iPhone: Настройки → Календарь → Учётные записи → Добавить
учётную запись → Другое → Подписной календарь. Google Calendar: на
компьютере «Другие календари» → «+» → «Подписаться по URL».

Ограничения: календарь обновляется раз в неделю вместе с отчётом, а
подписные календари Apple и Google обновляются сами раз в несколько часов или
реже. Уведомлений у подписных календарей нет, поэтому для напоминаний есть
отчёт 6.

## 2. Топ-10 акций по росту за 3 месяца

`monthly_top_gainers.py`, workflow `monthly_top_gainers.yml`.
Расписание: 2-го числа каждого месяца, 12:00 UTC (15:00 МСК).

Скрипт сравнивает цену закрытия на начало и конец скользящего окна в 3 месяца
(по вчерашний день) и присылает топ-10 по проценту роста.

Список акций задан вручную словарём `WATCHLIST` в начале
`monthly_top_gainers.py` (31 тикер). Чтобы изменить список, отредактируйте
словарь прямо на GitHub; формат `"ТИКЕР": "Название",`. Для классов акций
используется дефис (`BRK-B`).

Лимит Twelve Data: данные запрашиваются пачками по 6 тикеров с паузой 75
секунд, поэтому на 31 тикер ожидается около 6-8 минут (таймаут workflow 20
минут). Акции без полных данных за окно пропускаются, в сообщении указано,
сколько реально учтено.

Скрипт сохраняет результат в `top10_companies.json` и коммитит его в
репозиторий, потому что от него зависит отчёт 3. Для этого нужны права на
запись (общая настройка, п. 3).

Рост цены за прошедший период это исторический факт, не прогноз и не
рекомендация.

## 3. Разбор компаний из топ-10

`company_deepdive.py`, workflow `company_deepdive.yml`.
Расписание: ежедневно 09:00 UTC (12:00 МСК), но сообщение приходит только в 10 дней после
отчёта 2: на следующий день компания #1, потом #2 и так до #10. В остальные
дни скрипт ничего не делает, это нормально.

По каждой компании: суть бизнеса, причины роста за период (из свежего
веб-поиска, а не из памяти модели), основные метрики, взгляд аналитиков и
риски. Генерация идёт через Claude API с инструментом веб-поиска
(`ANTHROPIC_API_KEY`, платный, оплата за использование). Оценка: порядка
3-5 центов за компанию, около 0,3-0,5 доллара в месяц на все десять. Точную
цифру смотрите в консоли Anthropic.

Состояние: `deepdive_sent_state.json` помнит, какие номера уже отправлены.
Номер помечается отправленным только после успешной отправки в Telegram,
иначе он повторится при следующем запуске.

Тестовый запуск без привязки к дате: Actions → Company Deep Dive → Run
workflow → в поле `test_rank` введите номер от 1 до 10. Сообщение придёт с
пометкой «ТЕСТОВЫЙ ЗАПУСК», а файл состояния не изменится.

Если отчёт 2 в какой-то месяц не отработал, `top10_companies.json` не
обновится, и отчёт 3 доиграет цикл по старому списку.

Разбор это синтез найденного в интернете на момент запроса. Полной или
единственно верной картины он не гарантирует и не является инвестиционной
рекомендацией.

## 4. Дайджест подкаста Morgan Stanley

`ms_insights_digest.py`, workflow `ms_insights_digest.yml`.
Расписание: ежедневно 18:00 UTC (21:00 МСК). Эпизоды выходят примерно между 9 и 14
часами по Нью-Йорку, поэтому более ранняя проверка отставала на день.

Скрипт берёт страницу «Thoughts on the Market» (транскрипты лежат прямо в
HTML), находит новые эпизоды и присылает краткое содержание на русском.

- Первый запуск ничего не присылает: он только запоминает текущие эпизоды
  как уже виденные.
- С `ANTHROPIC_API_KEY` пересказ и перевод делает Claude за один запрос
  (оценка: порядка 1-2 центов за эпизод). В запрос подставляется сегодняшняя
  дата, чтобы модель не путала годы. Без ключа или при ошибке API включается
  бесплатный запасной вариант: локальное выделение ключевых предложений и
  перевод MyMemory (качество ниже).
- Эпизод считается виденным только после успешной отправки в Telegram.
- Лимит Telegram 4096 символов соблюдается: слишком длинный текст
  обрезается с пометкой.
- Состояние хранится в `seen_podcasts.json`.

Если сайт начнёт блокировать запросы с серверов GitHub, в логе будет ошибка
на шаге загрузки страницы; на остальные отчёты это не влияет.

## 5. Статистика торгового журнала

`trading_journal_digest.py`, workflow `trading_journal_digest.yml`.
Расписание: 2-го числа каждого месяца, 09:00 UTC (12:00 МСК). Статистика считается за
прошлый календарный месяц, по `Close_Date`.

Журнал ведётся в Google-таблице. Доступ для скрипта: «Поделиться» → доступ
по ссылке, роль «Читатель». Затем ссылка вида
`https://docs.google.com/spreadsheets/d/<ID>/export?format=csv`
сохраняется в Secret `JOURNAL_SHEET_CSV_URL`. Ссылка открывает журнал всем,
у кого она есть, поэтому в репозиторий её класть нельзя.

### Колонки

Столбцы ищутся по названию, порядок не важен, пробелы в заголовках
игнорируются. Заголовок в первой строке:

```
Open_Date | Close_Date | Instrument | Direction | Open_Price | Close_Price | Result_R | Rule_Based | CFTC_Aligned | State | Setup | Notes | Open_Time | Close_Time | Stop_Price | Target_Price | Exit_Reason | CFTC_Level
```

| Колонка | Что вносить |
|---|---|
| `Open_Date`, `Close_Date` | даты `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД` |
| `Open_Time`, `Close_Time` | `ЧЧ:ММ`, всегда в одном часовом поясе (удобно московский) |
| `Instrument`, `Direction` | например `EURUSD`, `Long` / `Short` |
| `Open_Price`, `Close_Price` | цены входа и выхода |
| `Stop_Price`, `Target_Price` | стоп и цель, заданные при входе |
| `Result_R` | результат в R (десятичная запятая допустима) |
| `Exit_Reason` | `Стоп` / `Тейк` / `Вручную` / `По времени` |
| `Rule_Based` | `Да` / `Нет`: была ли сделка по системе |
| `CFTC_Aligned` | по потоку: `Да` / `Нет` / `Не проверял` |
| `CFTC_Level` | по уровню: `Да` / `Нет` / `Не проверял` |
| `State` | состояние при входе: `Усталость` / `Спокойствие` / `Азарт` |
| `Setup`, `Notes` | произвольный текст |

Определения CFTC (заполняйте всегда одинаково, по последнему отчёту,
вышедшему до входа):
- `CFTC_Aligned` (поток): направление сделки совпадает со стороной, где
  за неделю крупные спекулянты добавили больше контрактов.
- `CFTC_Level` (уровень): направление совпадает со стороной, где большинство
  позиций (строка «Long X% / Short Y%»).

Эти два показателя могут расходиться: например, 90% позиций в лонге, но
свежие контракты идут в шорт. Для акций и других инструментов вне отчёта CFTC
поля оставляйте пустыми.

`State` вносите в момент входа, а не после результата: задним числом
состояние подгоняется под исход, и статистика теряет смысл.

Строка без `Close_Date` и без `Result_R` считается открытой сделкой и
пропускается без предупреждений. Строку можно создать при входе и дописать
при закрытии.

### Что в отчёте

Всего сделок, винрейт, сумма и среднее R, затем разбивки: по инструментам,
дням недели закрытия, «по системе / дискреция», CFTC по потоку, CFTC по
уровню и их комбинации, длительность (внутри дня / свинг / позиционная),
причина выхода, план против факта (плановый R:R из стопа и цели против
фактического среднего выигрыша и проигрыша), состояние при входе, теги
сетапа. Если в группе меньше 3 сделок, показывается «недостаточно данных».

Вверху отчёта выводится блок «Проверьте данные в таблице». Он ловит дату
закрытия раньше открытия, знак `Result_R` против движения цены, стоп или цель
не с той стороны от цены входа, `Result_R`, не совпадающий с ценами при
заданном стопе, и нечитаемые строки. Раньше такие строки пропадали молча.

Статистика считается по вашим данным без внешних сигналов. На малом числе
сделок выводы шумные; опираться на них можно после нескольких десятков.

## 6. Напоминания о событиях календаря

`calendar_reminders.py`, workflow `calendar_reminders.yml`.
Расписание: каждые 10 минут, в минуты :04, :14, :24, :34, :44, :54.

Для USD-событий High и Medium присылает напоминание в Telegram:
- «за ~час» (окно 40-65 минут до события) для High и Medium;
- «за ~15 минут» (окно 5-25 минут) только для High;
- события с одинаковым временем (например, четыре строки CPI) приходят одним
  сообщением.

Каждое напоминание отправляется один раз на событие и этап; список
отправленных хранится в `reminded_events.json` и чистится от записей старше
3 дней.

Почему окна и два напоминания, а не «ровно за 5 минут»: расписание GitHub
best-effort, и один пропущенный запуск не должен лишать вас предупреждения.

## Надёжность расписаний

GitHub документирует триггер `schedule` как best-effort: запуски могут
задерживаться в часы высокой нагрузки, к которым относится начало каждого
часа, а при достаточно высокой нагрузке часть задач в очереди может быть
сброшена. Это наблюдалось на практике: 14.10.2026 при расписании «каждые 30
минут» за ~14 часов было 4 запуска вместо ~28, и напоминание о CPI в 15:30
МСК не пришло. Поэтому:

- ни один отчёт не гарантирован по времени; если отчёт не пришёл, запустите
  его вручную (Run workflow);
- для помесячных отчётов (2 и 5) пропуск означает ожидание до следующего
  месяца, пока вы не запустите их вручную;
- в публичных репозиториях GitHub автоматически отключает расписания после
  60 дней без активности в репозитории;
- для событий, которые нельзя пропустить, надёжнее запускать workflow
  внешним планировщиком (например, cron-job.org) через GitHub API; для этого
  нужен токен с правом только на Actions этого репозитория.

С 19 октября по 19 ноября 2026 GitHub постепенно переводит метку
`ubuntu-latest` на Ubuntu 26.04. Если после этого какой-то workflow начнёт
падать, временный откат: заменить в нём `runs-on: ubuntu-latest` на
`runs-on: ubuntu-24.04`.

## Известные ограничения

- Календарь Forex Factory: неофициальный, но давно используемый бесплатный
  фид. Если он недоступен, в отчётах появится «нет данных» по календарю.
- Twelve Data, бесплатный тариф: 8 кредитов в минуту и 800 в день; при
  большом числе тестовых запусков дневной лимит можно исчерпать.
- Отчёты 3 и 4 используют платный Claude API; без ключа отчёт 4 работает в
  запасном режиме, отчёт 3 не работает.
- Суммы стоимости выше ориентировочные; точные цифры в консолях
  провайдеров.
