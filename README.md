# Отчёт 5: напоминания о календарных событиях в Telegram

Файлы: `calendar_reminders.py`, `.github/workflows/calendar_reminders.yml`

Секретов не требует сверх того, что уже в репозитории.

## Зачем это нужно
Экономический календарь из Отчёта 1 переносится в календарь телефона через
подписку (ICS), но **подписные календари не поддерживают уведомления** —
это ограничение самих Apple Calendar / Google Calendar, а не наших файлов.
Apple при подписке по умолчанию убирает оповещения ("Remove Alerts"),
Google вообще не даёт настроить напоминания для подписных календарей через
интерфейс. Поэтому напоминания шлём напрямую в Telegram, где мы полностью
контролируем время доставки.

## Что делает
1. Каждые 10 минут проверяет тот же бесплатный календарь Forex Factory,
   что и Отчёт 1
2. Если какое-то событие (High/Medium impact, USD) должно начаться через
   10-20 минут — присылает напоминание в Telegram
3. Не шлёт повторно одно и то же событие (список уже отправленных
   напоминаний хранится в `reminded_events.json`, обновляется автоматически)

## Насколько это надёжно

GitHub документирует расписания (`schedule: cron`) как best-effort: "в часы
высокой нагрузки, включая начало каждого часа, запуск может задержаться, а
при достаточно высокой нагрузке часть задач в очереди может быть сброшена".
Это не теория: 14.10.2026 при расписании "каждые 30 минут" GitHub выполнил
4 запуска за ~14 часов вместо ~28, и ни один не попал в окно перед
отчётом CPI в 15:30 МСК. Напоминание не пришло. Раньше здесь было написано,
что окно 30-60 минут "гарантирует" предупреждение; это было неверно:
окно защищает от задержки, но не от запуска, которого не было вовсе.

Что сделано после этого:
1. Запуск каждые 10 минут в минуты :04, :14, :24 ... (не в :00 и :30), чтобы
   у GitHub было больше шансов и мы не попадали в самые загруженные моменты
2. Два напоминания для High-событий: за ~час (окно 40-65 мин) и за ~15 минут
   (окно 5-25 мин). Medium-события получают только первое
3. События с одинаковым временем (например, 4 строки CPI) приходят одним
   сообщением

Это снижает риск, но не убирает его. Если событие критично, держите его и
в еженедельном отчёте/календаре, а при повторных пропусках запускайте
workflow внешним планировщиком (cron-job.org и т.п.) через GitHub API.

## Сколько это стоит бесплатных минут GitHub Actions
Проверка каждые 30 минут = 48 запусков в день ≈ 1440 запусков в месяц.
GitHub считает минуты **округляя каждый запуск вверх до целой минуты**,
даже если сам скрипт отрабатывает за 10-20 секунд — то есть это ≈1440
"расходуемых" минут в месяц только на этот отчёт.

**Если ваш репозиторий публичный (Public)** — это не имеет значения
вообще: у публичных репозиториев минуты GitHub Actions полностью
бесплатны и не ограничены.

**Если репозиторий приватный (Private)** — бесплатный лимит для личного
аккаунта обычно 2000 минут в месяц, и 1440 из них уйдёт на одни только
напоминания, оставляя не очень много запаса на остальные отчёты в этом же
репозитории (ежемесячный топ-10 акций — самый "дорогой" из остальных,
около 100-120 минут за один прогон).

Прежде чем включать этот отчёт, стоит проверить два момента:
1. **Публичный у вас репозиторий или приватный** — Settings репозитория,
   внизу общей страницы, или просто посмотрите на бейдж рядом с
   названием репозитория на GitHub ("Public"/"Private")
2. **Сколько минут уже реально расходуется** — в настройках аккаунта:
   Settings (аккаунта, не репозитория) → Billing and plans → Plans and
   usage — там точная цифра за текущий период, надёжнее любых прикидок

## Как добавить
1. Создать `calendar_reminders.py` в корне репозитория
2. Создать `.github/workflows/calendar_reminders.yml`
3. Включить права на запись для Actions (если ещё не включали для этого
   репозитория): Settings → Actions → General → Workflow permissions →
   Read and write permissions
4. Actions → "Calendar Event Reminders" → Run workflow для проверки

## Важно понимать
- Это ежедневный фоновый процесс, который срабатывает каждые 10 минут
  **круглосуточно** — в отличие от остальных отчётов, которые запускаются
  1 раз в день/неделю/месяц. Из-за этого он расходует заметно больше
  бесплатных минут GitHub Actions (для приватного репозитория лимит
  2000 минут/месяц — при запуске каждые 10 минут и коротком времени
  выполнения (секунды) обычно укладывается с запасом, но если у вас
  приватный репозиторий и уже много других частых автоматизаций — стоит
  иметь это в виду)
- Реальная точность зависит от того, насколько GitHub задержит конкретный
  запуск — обычно укладывается в объявленное окно, но абсолютной гарантии
  по срокам GitHub не даёт ни при каких настройках

# Отчёт 6: ежедневный разбор компаний из топ-10 (с веб-поиском)

Файлы: `company_deepdive.py`, `.github/workflows/company_deepdive.yml`

Этот отчёт зависит от Отчёта 2 (топ-10 акций) — `monthly_top_gainers.py`
теперь дополнительно сохраняет список топ-10 в файл `top10_companies.json`.
Начиная со следующего дня после публикации топ-10, этот отчёт присылает
по одному подробному разбору компании в день, по порядку места в рейтинге
— 10 дней подряд, затем тишина до следующего месяца.

## Что присылает по каждой компании
1. Суть бизнеса
2. Почему именно такой рост цены за период (это ищется через актуальный
   веб-поиск, а не берётся из "памяти" модели — иначе причины роста часто
   были бы или устаревшими, или попросту придуманными)
3. Основные метрики (выручка, маржинальность, оценка, капитализация)
4. Инвестиционный прогноз — мнения аналитиков, риски

Расписание: ежедневно в 09:00 UTC. В большинстве дней месяца отчёт
ничего не присылает — это ожидаемое поведение, не ошибка (активен только
в 10-дневном окне после публикации топ-10).

## Как добавить
1. Обязательно сначала обновить `monthly_top_gainers.py` и
   `.github/workflows/monthly_top_gainers.yml` (новые версии — они теперь
   сохраняют `top10_companies.json` и коммитят его обратно, для этого
   нужны права на запись, как и в других местах)
2. Добавить `company_deepdive.py` и
   `.github/workflows/company_deepdive.yml`
3. Секретов сверх уже существующих не нужно (использует тот же
   `ANTHROPIC_API_KEY`, что и подкаст-дайджест)
4. Проверить можно только после того, как хотя бы раз успешно отработает
   `monthly_top_gainers.py` и создаст `top10_companies.json` — до этого
   `company_deepdive.py` просто будет писать в лог "нет файла, нечего
   делать"

## Стоимость
Веб-поиск у Claude — **$10 за 1000 запросов** ($0.01 за один поиск), плюс
обычная стоимость токенов. Модель за один разбор обычно делает 2-3 поиска.
Один разбор компании — примерно **$0.03-0.05**. На 10 компаний в месяц —
около **$0.30-0.50/месяц** сверх того, что уже тратится на подкаст-дайджест.

## Важно понимать
- Если отчёт о топ-10 не придёт в какой-то месяц (например, упал в
  рейт-лимит Twelve Data) — `top10_companies.json` не обновится, и
  `company_deepdive.py` продолжит доигрывать цикл по старому списку.
  Это разумное поведение по умолчанию, но стоит иметь в виду
- Данные о "причинах роста" и прогнозы — это синтез того, что Claude
  нашёл через поиск на момент запроса, не гарантированно полная или
  единственно верная картина — как и любой инвестиционный комментарий
